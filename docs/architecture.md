# 架构与扩展

当前网站采用 Astro 5 静态生成。MDX 与结构化资料在构建时合成 HTML，浏览器按页面加载少量原生 TypeScript。GitHub Actions 检查代码并构建 `dist/`，GitHub Pages 托管这些静态文件。

## 数据与页面边界

| 层     | 位置                                         | 职责                                   |
| ------ | -------------------------------------------- | -------------------------------------- |
| 内容   | `src/content/projects/`、`src/content/blog/` | 项目案例、文章和媒体说明               |
| Schema | `src/content.config.ts`                      | 用枚举、必填字段和 URL 约束验证内容    |
| 资料   | `src/data/`                                  | 姓名、教育背景、技术方向、外部入口     |
| 页面   | `src/pages/`                                 | 路由、静态集合查询、SEO 输出           |
| 呈现   | `src/layouts/`、`src/components/`            | 布局、卡片、项目模板和阅读组件         |
| 交互   | `src/scripts/`                               | 筛选、搜索、主题、菜单、图库和阅读辅助 |
| 样式   | `src/styles/`                                | 颜色、排版、响应式与动效变量           |
| 部署   | `.github/workflows/deploy.yml`               | Linux 检查、产物上传与 Pages 发布      |

Content Collections 使用 Astro 5 的 `glob()` loader；文件名产生内容 ID。文章与项目通过 ID 关联，页面组件负责展示，新增内容沿用已有模板。

## 站点路径

`SITE_URL` 表示源地址，生产值为 `https://bobby23327.github.io`；`SITE_BASE` 表示部署前缀，生产值为 `/2hard4meTAT/`。本地开发默认使用 `http://localhost:4321` 和 `/`。

路径工具集中处理站内链接与资源前缀，页面、组件、RSS 和 SEO 输出使用同一配置。内容资料保存相对站点根目录的路径，例如 `/images/cover.svg`。更换托管路径时调整构建配置即可，内容中的文件路径保持稳定。Astro 自动处理打包资源的基础路径。参见 [Astro 配置参考](https://docs.astro.build/en/reference/configuration-reference/#base)。

## 功能在哪里运行

| 功能                                 | 当前或未来运行位置               | 持久化要求                           |
| ------------------------------------ | -------------------------------- | ------------------------------------ |
| 项目、文章、详情、关于、404          | 构建时生成 HTML                  | Git 中的 MDX 和资料                  |
| RSS、Sitemap、SEO 元数据             | 构建时生成                       | `SITE_URL`、`SITE_BASE` 与内容元数据 |
| 项目分类、标签、关键词与排序         | 浏览器筛选已有卡片               | URL 查询参数用于分享                 |
| 博客搜索与标签                       | 浏览器筛选已有文章摘要           | URL 查询参数                         |
| 主题、移动导航、图库、复制、阅读进度 | 浏览器                           | 主题保存在本地存储                   |
| GitHub 统计                          | 优先构建时获取，按需增加独立 API | 可选缓存与更新时间                   |
| 在线编辑与发布                       | CMS 或受保护的独立 API           | 内容版本、草稿、审计记录             |
| 评论与留言                           | 独立 API                         | 正文、审核状态、时间与关联文章       |
| 访问统计                             | 独立统计服务                     | 聚合计数与短期原始记录               |
| Agent Demo                           | 独立服务中的受控任务             | 任务状态、运行记录与可选产物         |
| 动态项目进度                         | 独立 API 或构建时同步            | 版本化进度记录                       |

页面文本、主要图像与字体均由站内资源提供。外部视频和可选 API 作为补充内容，网络异常时保留正文和静态说明。

## 逐步增加动态功能

GitHub Pages 提供静态托管，动态功能使用独立服务。优先在 Actions 构建期间同步公开 GitHub 信息，将允许展示的字段和 `fetchedAt` 写入构建数据。需要实时刷新时再添加 API，并配置精确的跨域来源、身份验证和限流。GitHub Pages 的工作方式见 [官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

上游失败时可使用注明时间的历史缓存；缓存缺失时返回明确的暂不可用状态。主页面继续展示 MDX 中的项目记录。

CMS 可以先采用 Git 内容源与审核后构建的发布方式。需要在线草稿时，再增加身份验证、版本冲突检测和发布权限。外部投稿优先使用受限 Markdown；MDX 作为可执行内容，只接受受信任作者维护。

## 存储选择

公开数据缓存适合具有过期策略的缓存服务；评论、审核和任务状态使用数据库；截图、文档和任务产物使用对象存储。根据所需的一致性、事务与访问控制选择服务。

评论保存为带 ID 的独立记录，字段包含文章 ID、正文、创建时间、审核状态和审核记录。公开索引只纳入已审核内容。媒体上传前由服务端校验类型与大小，再分配受控对象路径；私有草稿和公开资源分别管理访问权限。

审核撤回、额度扣减与并发任务锁需要对应的一致性和原子操作保障。缓存用于减少读取成本，关键状态以数据库为准。

## API 密钥与输入边界

构建期同步所需凭据放入 GitHub Actions Secrets；动态接口的密钥放入 API 服务环境变量。`PUBLIC_` 变量、MDX frontmatter、HTML、客户端脚本和生成后的 `dist/` 都按公开信息处理。

每个接口先校验 HTTP 方法、内容类型、请求大小和字段 Schema，使用允许的字段构造下游请求。用户内容按文本输出，链接仅接受允许的协议。管理接口验证身份和权限，基于 Cookie 的写入增加 CSRF 防护与来源校验。日志记录请求 ID、错误类型和耗时，凭据与敏感输入在日志前脱敏。

## 评论、限流与服务异常

评论流程为“提交 → 待审核 → 公开 / 拒绝”。提交接口限制长度、链接数量和频率，返回记录 ID 与待审核状态。审核操作记录操作者和时间，公开读取只查询已发布状态。删除与撤回需处理缓存失效和传播延迟。

限流以服务端验证的身份和来源为依据；配置每分钟请求数、并发任务数和每日成本预算，使用具名常量并通过环境配置调整。触发限制返回 `429` 与 `Retry-After`，严格预算与并发控制使用支持原子操作的存储。

接口用明确的 HTTP 状态表达结果：`400` 参数错误、`401/403` 身份或权限问题、`404` 资源缺失、`409` 版本冲突、`429` 限流、`503` 暂时不可用。对外返回稳定错误码、可读说明和请求 ID；服务端记录原始异常。重试用于可恢复错误，并设置超时、次数上限和退避策略。写入采用幂等键，避免重试重复提交。

Agent Demo 需明确工具允许范围、执行时间、资源预算和取消机制。任务在隔离环境中执行，服务端保存状态，浏览器轮询或订阅结果。模型密钥、主机文件和内部网络保持服务端隔离，公开示例使用预先准备的输入与受限工具。

## 迁移到 Astro SSR

当页面需要每次请求的数据时，可选择支持 Astro 适配器的服务端托管平台，并按路由决定预渲染或按需渲染。迁移时重新检查运行时、环境变量、函数打包、部署前缀和静态资源路径，再验证预览环境。当前 GitHub Pages 工作流继续适用于静态输出。参见 [Astro 按需渲染指南](https://docs.astro.build/en/guides/on-demand-rendering/)。
