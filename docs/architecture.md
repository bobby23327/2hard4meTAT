# 架构与扩展

当前网站采用 Astro 5 静态生成。MDX 与结构化资料在构建时合成 HTML，浏览器按页面加载少量原生 TypeScript。`dist/` 包含完整主要内容，可迁移到支持静态目录与 404 的托管平台。

## 数据与页面边界

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 内容 | `src/content/projects/`、`src/content/blog/` | 项目案例、文章和媒体说明 |
| Schema | `src/content.config.ts` | 用枚举、必填字段和 URL 约束验证内容 |
| 资料 | `src/data/` | 姓名、教育背景、技术方向、外部入口 |
| 页面 | `src/pages/` | 路由、静态集合查询、SEO 输出 |
| 呈现 | `src/layouts/`、`src/components/` | 布局、卡片、项目模板和阅读组件 |
| 交互 | `src/scripts/` | 筛选、搜索、主题、菜单、图库和阅读辅助 |
| 样式 | `src/styles/` | 颜色、排版、响应式与动效变量 |

Content Collections 使用 Astro 5 的 `glob()` loader；文件名产生内容 ID。文章与项目通过 ID 关联。页面组件负责展示，新增内容沿用已有模板。

## 功能在哪里运行

| 功能 | 当前或未来运行位置 | 持久化要求 |
| --- | --- | --- |
| 项目、文章、详情、关于、404 | 构建时生成 HTML | Git 中的 MDX 和资料 |
| RSS、Sitemap、SEO 元数据 | 构建时生成 | `SITE_URL` 与内容元数据 |
| 项目分类、标签、关键词与排序 | 浏览器筛选已有卡片 | URL 查询参数用于分享 |
| 博客搜索与标签 | 浏览器筛选已有文章摘要 | URL 查询参数 |
| 主题、移动导航、图库、复制、阅读进度 | 浏览器 | 主题保存在本地存储 |
| GitHub 统计 | 优先构建时获取，按需增加缓存 API | 可选 KV 缓存与更新时间 |
| 在线编辑与发布 | CMS 或受保护的服务端 API | 内容版本、草稿、审计记录 |
| 评论与留言 | 服务端 API | 正文、审核状态、时间与关联文章 |
| 访问统计 | 平台统计，或服务端收集接口 | 聚合计数与短期原始记录 |
| Agent Demo | 服务端受控任务 | 任务状态、运行记录与可选产物 |
| 动态项目进度 | 服务端 API 或构建时同步 | 版本化进度记录 |

页面文本、主要图像与字体均由站内资源提供。外部视频和可选 API 作为补充内容，网络异常时保留正文和静态说明。

## 逐步接入 EdgeOne Functions

保持现有 SSG 构建，先为一个具体需求添加 `/api/` 接口。按官方目录约定，在项目根目录创建 `edge-functions/api/` 或 `cloud-functions/api/`。轻量缓存、参数校验适合 Edge Functions；需要 Node.js 库、较长处理时间的任务可评估 Cloud Functions。目录映射与本地调试方式以启用时的平台版本为准。参见 [Functions 概览](https://pages.edgeone.ai/document/pages-functions-overview) 与 [Edge Functions](https://pages.edgeone.ai/document/edge-functions)。

建议先实现 GitHub 信息同步：服务端请求公开仓库，响应只暴露允许展示的字段，并附 `fetchedAt`。上游失败时可返回注明时间的历史缓存；没有可用缓存时返回明确的暂不可用状态。主页面继续展示 MDX 中的项目记录。

CMS 可以先采用 Git 内容源与审核后构建的发布方式。需要在线草稿时，再增加身份验证、版本冲突检测和发布权限。外部投稿优先使用受限 Markdown；MDX 作为可执行内容，只接受受信任作者维护。

## 存储选择

KV 适合公开数据缓存、配置和允许延迟同步的计数；Blob 适合媒体、文档、任务产物和按路径组织的对象。平台当前文档中，KV 在 Edge Functions 中使用；Blob 支持 Edge 与 Cloud Functions。配置前确认账户额度、运行环境和对象大小限制。参见 [存储概览](https://pages.edgeone.ai/document/storage-overview)。

KV 采用最终一致性，跨节点读取可能暂时得到旧值。因此审核撤回、严格额度扣减、并发任务锁等安全决策应选择具有所需一致性与原子语义的存储或专用服务。平台建议即时全局一致场景评估 Blob 的强一致读取；应用仍须独立处理并发更新和幂等性。参见 [KV 文档](https://pages.edgeone.ai/document/kv-storage)。

评论可保存为带 ID 的独立记录，字段包含文章 ID、正文、创建时间、审核状态和审核记录。公开索引只纳入已审核内容。媒体上传前由服务端校验类型与大小，再分配受控对象路径；私有草稿和公开资源分别管理访问权限。

## API 密钥与输入边界

密钥放入平台服务端环境变量，由 Functions 从运行环境读取；构建时同步使用仅对构建过程开放的凭据。浏览器只请求本站 API。`PUBLIC_` 变量、MDX frontmatter、HTML、客户端脚本和生成后的 `dist/` 都按公开信息处理。

每个接口先校验 HTTP 方法、内容类型、请求大小和字段 Schema；使用允许的字段构造下游请求。用户内容按文本输出，链接仅接受允许的协议。管理接口验证身份和权限，基于 Cookie 的写入增加 CSRF 防护与来源校验。日志记录请求 ID、错误类型和耗时，凭据与完整敏感输入在日志前脱敏。

## 评论、限流与服务异常

评论流程为“提交 → 待审核 → 公开 / 拒绝”。提交接口限制长度、链接数量和频率，返回记录 ID 与待审核状态。审核操作记录操作者和时间，公开读取只查询已发布状态。删除与撤回需处理缓存失效和传播延迟。

限流以服务端验证的身份和来源为依据；配置每分钟请求数、并发任务数和每日成本预算，使用具名常量并通过环境配置调整。触发限制返回 `429` 与 `Retry-After`。最终一致 KV 可做粗粒度计数，严格预算与并发控制应使用支持原子操作的方案。

接口用明确的 HTTP 状态表达结果：`400` 参数错误、`401/403` 身份或权限问题、`404` 资源缺失、`409` 版本冲突、`429` 限流、`503` 暂时不可用。对外返回稳定错误码、可读说明和请求 ID；服务端记录原始异常。重试只用于可恢复错误，并设置超时、次数上限和退避策略。写入采用幂等键，避免重试重复提交。

Agent Demo 需明确工具允许范围、执行时间、资源预算和取消机制。将任务放入隔离环境，服务端保存状态，浏览器轮询或订阅结果。模型密钥、主机文件和内部网络保持服务端隔离，公开示例优先使用预先准备的输入与受限工具。

## 迁移到 Astro SSR

当页面确实依赖每次请求的数据时，再为对应路由引入服务端渲染。使用官方 `@edgeone/astro` 适配器，按需选择预渲染路由。当前官方适配器默认构建目录为 `.edgeone`；迁移时必须重新检查构建产物、函数打包、静态资源路径、运行时版本和 `edgeone.json`，再执行预览部署验证。SSG 的 `dist` 设置适用于本版静态产物。参见 [官方 Astro 指南](https://pages.edgeone.ai/document/framework-astro)。
