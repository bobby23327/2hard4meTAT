本文以[视界限](/projects/horizon)的双窗口交互方向为背景，给出独立的坐标推导与验证思路。示例数值用于演示，发布日为本站整理日期。

## 一个坐标，需要带上它的空间

“鼠标在 `(120, 80)`”缺少必要的信息。它可能是窗口内容区域中的位置，也可能是 Viewport、场景或某个节点内部的位置。同样的数值，在不同空间中具有不同含义。

Godot 区分局部、画布、Viewport 与屏幕等坐标空间，变换矩阵负责它们之间的转换。双窗口交互需要先选定一个共同空间，再连接两侧的变换链。[Godot 2D coordinate systems](https://docs.godotengine.org/en/4.6/engine_details/architecture/2d_coordinate_systems.html)

这里使用屏幕空间作为共同空间，约定 `T_A` 把窗口 A 的游戏空间坐标映射到屏幕空间，`T_B` 对窗口 B 执行相同方向的映射。

## 先推导，再代入数值

从 A 中的点寻找它在 B 中对应的位置，可以分成两个步骤：

```text
屏幕坐标 = T_A × A 中坐标
B 中坐标 = inverse(T_B) × 屏幕坐标

合并后：B 中坐标 = inverse(T_B) × T_A × A 中坐标
```

在两个窗口均无缩放、无旋转、相机原点一致的简化情况下，变换只包含平移。假设 A 的内容原点是 `(240, 160)`，B 的内容原点是 `(200, 150)`，那么 A 中的 `(120, 80)` 对应屏幕上的 `(360, 240)`，再对应 B 中的 `(160, 90)`。

这些前提应写进验证用例。加入相机平移、画布缩放或显示缩放后，应更新完整变换，而不是继续把窗口位置相减当作通用公式。

## 把转换写成单一入口

下面使用 `System.Numerics` 展示一个独立的仿射变换示例。它接收已经整理好的同一屏幕空间变换；Godot 工程中的窗口与画布适配由边界层提供。

```csharp
public static Vector2 MapBetweenWindows(
    Vector2 sourcePoint,
    Matrix3x2 sourceToScreen,
    Matrix3x2 targetToScreen)
{
    if (!Matrix3x2.Invert(targetToScreen, out var screenToTarget))
        throw new InvalidOperationException("目标窗口变换必须可逆。");

    var screenPoint = Vector2.Transform(sourcePoint, sourceToScreen);
    return Vector2.Transform(screenPoint, screenToTarget);
}
```

逐步转换让方向一目了然，也避免混淆不同矩阵库的乘法约定。调用方还需要校验数值是否有限、内容区域是否有效，以及本轮输入是否对应同一份窗口布局。

## 窗口位置与内容原点需要区分

原生窗口和嵌入窗口的定位语义不同。Godot 的 `Window.position` 在原生窗口模式下使用屏幕坐标；嵌入模式下的位置相对于所属 Viewport。应先确定窗口模式，再读取并组合对应变换。[Godot Window](https://docs.godotengine.org/en/4.6/classes/class_window.html)

边框、标题栏、内容拉伸和 DPI 缩放都应在窗口适配层统一处理。映射核心只接受已经约定好的输入，业务代码便能专注于“哪个点与哪个点重合”。跨屏场景还需要实际核对系统和显示后端提供的坐标单位。

## 布局快照与世界状态分开保存

一次交互可以读取同一份布局快照，其中包含两个窗口的位置、尺寸与变换。这样，命中检测和后续操作使用同一时刻的几何关系，便于复现边界问题。

世界实体则持有自己的稳定标识与业务状态。窗口可以关闭、重建或失去焦点，实体的生命期需要由玩法规则决定。表现对象重建时，应通过实体标识恢复视图，而不是把场景节点当作唯一的数据来源。

拖动过程也值得独立建模：开始拖动时记录起点与目标，更新时重新映射，释放时提交操作，失焦时进入明确的取消或暂停流程。每个转移都应具有唯一的结束语义。

## 一组有用的验证案例

| 场景 | 检查目标 |
| --- | --- |
| 窗口仅发生平移 | 数值与手工计算一致 |
| 两侧具有不同缩放 | 正反转换在误差范围内闭合 |
| 窗口边界恰好接触 | 命中范围的包含规则明确 |
| 拖动中失焦 | 交互进入规定的结束状态 |
| 表现对象重建 | 实体身份与业务状态保持一致 |
| 跨屏与 DPI 变化 | 坐标单位与内容区域重新校准 |

数学推导可以独立验证，窗口系统行为则需要实机测试。后续项目记录应分别呈现这两类证据，并写明操作系统、显示缩放、Godot 版本与窗口模式。
