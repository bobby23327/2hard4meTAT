## 项目概况

Mcards 是一个魔法学院主题的卡牌叙事模拟原型。玩家通过卡牌组合推动事件，游戏系统负责条件匹配、效果结算与世界时间推进。项目的工程重点是让玩法规则与 Unity 表现层各自保持清晰的职责。

## 问题与约束

叙事内容会持续增加，同一张卡牌可能参与多个配方，事件还会受到世界时间与角色状态影响。规则需要支持组合与调试，界面则需要稳定地读取模拟结果。两者通过显式接口协作，能让内容修改与交互调整保持局部影响。

## 系统架构

基于 asmdef 划分内容、模拟、应用与表现四个层次。内容层描述规则；纯 C# 模拟层执行规则；应用层协调命令与时间；表现层把只读状态转换为 Unity 场景与界面。

```text
Unity 表现 → 应用命令 → 模拟核心
    ↑                     ↓
    └────── 只读快照 ──────┘
                     ↑
             Recipe / Condition / Effect
```

## 关键实现

- **Recipe / Condition / Effect**：分别描述配方、前置条件和状态变化，方便独立编写与组合内容。
- **ProcessGraph**：把阶段推进表达为流程节点和连接关系，集中讨论分支、等待与完成语义。
- **WorldTime / CommandQueue**：将玩家请求与世界调度放进同一套时间语义，明确同一时刻的处理顺序。
- **内容编辑与调试工具**：围绕内容引用、条件结果与流程状态提供检查入口。

## 设计权衡

数据驱动会增加内容校验的责任。配置越灵活，越需要在加载阶段检查标识符、引用和取值范围。纯 C# 核心也需要边界类型，把场景对象转为稳定标识，再将结果交给表现层解释。

## 技术难点

值得持续关注的场景是同一时刻发生多个事件：一个效果可能移除实体，后续命令仍引用该实体。处理顺序、失效引用和重复提交都需要明确语义。快照发布应对应完整结算后的状态，避免界面观察到中间过程。

## 测试与验证计划

优先为配方匹配、效果结算、时间边界和命令顺序建立独立测试；再用固定初始状态与命令序列检查结果一致性。内容层补充引用校验，表现层补充卡牌拖放、场景切换与状态刷新验证。测试记录、覆盖范围和实机演示将在可公开材料整理后补齐。
